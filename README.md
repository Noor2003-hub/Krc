# نظام الفواتير والرسوم – مركز الكويت للتأهيل (KRC)

موقع داخلي لمسؤولَين اثنين: تسجيل الفواتير يدوياً (كاش / رابط دفع / ومض / أخرى)، متابعة المشتركين الثابتين شهر بشهر، المصروفات الشهرية (إيجار، رواتب، أخرى)، لوحة تحليلات فيها المحصّل والمصروفات والصافي، وطباعة سند قبض.

**التقنيات:** Next.js 16 · Supabase (قاعدة البيانات وتسجيل الدخول) · Tailwind CSS · النشر على Vercel.

---

## خطوات التشغيل (مرة واحدة)

### 1) مشروع Supabase
1. أنشئ مشروع جديد في [supabase.com](https://supabase.com).
2. افتح **SQL Editor**، الصق محتوى الملف `supabase/migrations/0001_init.sql` كاملاً، واضغط **Run**. بعده نفس الشي للملف `supabase/migrations/0002_expenses.sql`.
3. من **Project Settings → API** انسخ:
   - `Project URL`
   - مفتاح `anon` / `publishable`
   - مفتاح `service_role` (سري، للخطوة 2 فقط)
4. **Authentication → Sign In / Providers → Email**: خلّ Email مفعّل، و**اقفل "Allow new users to sign up"** (ما في تسجيل حسابات من برّا).
5. **Authentication → URL Configuration**: حط `Site URL` = رابط الموقع على Vercel، وأضف نفس الرابط + `/**` في Redirect URLs.
6. **Authentication → Email Templates → Reset Password**: غيّر الرابط في القالب إلى:
   ```
   {{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery&next=/reset-password
   ```
   (عشان رابط «إعادة تعيين كلمة المرور» يشتغل حتى لو انفتح من جهاز ثاني.)

### 2) إنشاء حسابات المسؤولين
من جهازك (مرة واحدة فقط):
```bash
npm install
SUPABASE_URL="https://xxxx.supabase.co" \
SUPABASE_SERVICE_ROLE_KEY="service-role-key" \
INITIAL_PASSWORD="كلمة-المرور-المؤقتة" \
npm run create-admins
```
ينشئ الحسابين (الأسماء والإيميلات في `scripts/create-admins.mjs`):
- نمر زايد — nimerzayed@icloud.com
- سائد طه — saedtaha1975@gmail.com

كلمة المرور مؤقتة: الموقع يعرض تنبيه لحد ما كل مسؤول يغيّرها من **الإعدادات**.
> لا تحط كلمة المرور ولا مفتاح `service_role` في الكود أو على GitHub.

### 3) النشر على Vercel
1. ارفع المجلد على GitHub (مستودع **خاص**).
2. في Vercel: **Add New → Project** واختر المستودع.
3. أضف متغيرات البيئة:
   | الاسم | القيمة |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | مفتاح anon / publishable |
   | `NEXT_PUBLIC_SITE_URL` | رابط الموقع، مثلاً `https://krc-invoices.vercel.app` |
4. **Deploy**. بعدها ارجع لخطوة 1.5 وحدّث `Site URL` لو تغيّر الرابط.

> ملاحظة: خطة Vercel المجانية (Hobby) للاستخدام غير التجاري فقط. للتشغيل الفعلي للمركز استخدم خطة Pro أو استضافة تسمح بالاستخدام التجاري.
> مشروع Supabase المجاني يتوقف لو ما انستخدم أسبوع كامل، ويرجع يشتغل من لوحة Supabase.

### تشغيل محلي
```bash
cp .env.example .env.local   # وعبّي القيم
npm install
npm run dev                  # http://localhost:3000
npm test                     # اختبارات قاعدة «عن شهر» والمبلغ بالحروف والتحليلات
```

## كيف يشتغل

| الصفحة | المسار |
|---|---|
| تسجيل الدخول | `/login` |
| لوحة التحكم والتحليلات | `/` |
| الفواتير (بحث، فلاتر، تصدير Excel) | `/invoices` |
| تسجيل فاتورة / تعديل | `/invoices/new` · `/invoices/[id]/edit` |
| تفاصيل الفاتورة + سجل التعديلات | `/invoices/[id]` |
| سند قبض للطباعة / PDF | `/receipt/[id]` |
| المشتركين الثابتين | `/subscribers` |
| المصروفات (إضافة، تعديل، حذف، ملخص 6 شهور) | `/expenses` |
| الإعدادات (الاسم، كلمة المرور، المسؤولين، يوم الفصل) | `/settings` |

**قاعدة «عن شهر»:** الفاتورة من يوم 1 لغاية يوم الفصل (افتراضي 15) ← لنفس الشهر. بعد يوم الفصل ← مقدم للشهر اللي بعده. تنحسب تلقائياً وتقدر تتغير يدوياً. يوم الفصل يتعدّل من الإعدادات.

**المصروفات:** كل مصروف له نوع (إيجار / رواتب / مصروفات أخرى) وشهر يخصه وتاريخ صرف. لوحة التحكم تعرض المحصّل، اللي اتصرف، والصافي = المحصّل − المصروفات، لكل شهر.

**التكرار:** لو المشترك عنده فاتورة عن نفس الشهر، النظام يوقف الحفظ ويطلب تأكيد «حفظ رغم التكرار».

**الحماية:** كل الجداول محمية بـ Row Level Security: بس الحسابات الموجودة في جدول `admins` تقدر تقرأ أو تكتب. سجل التعديلات ما ينمسح ولا يتعدّل، وكل مسؤول يعدّل اسمه هو بس.

**بيانات التواصل في سند القبض** (التلفون، الإنستغرام، الإيميل) في أول ملف `app/receipt/[id]/page.tsx`.
